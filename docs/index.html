ШАГ 01

Соберите программу

Установите Git и Rust с Cargo. На Windows для стандартного MSVC toolchain нужны Visual Studio Build Tools с компонентами C++ и Windows SDK. После установки откройте новый терминал.

Получить исходники и собрать
git clone https://github.com/SWDevStudio/ccwatch.git
cd ccwatch
cargo build --release

Запустите собранный бинарник командой для своей системы:

Windows · PowerShell

.\target\release\ccwatch.exe

Из корня проекта также работает обёртка .\ccwatch.cmd.

macOS / Linux

./target/release/ccwatch

Для интерактивного режима используйте обычный терминал.

Команда из любой папки

cargo install --path .
ccwatch --help

Каталог Cargo bin должен быть в PATH: обычно ~/.cargo/bin, на Windows — %USERPROFILE%\.cargo\bin. Rust-версии и её встроенному хуку Node.js не нужен. Файлы ccwatch-hook.js и каталог prototype/ относятся к Node-варианту.

ШАГ 02

Откройте первую сессию

  1. Запустите задачу в Claude Code. Монитор ищет сессии на этой машине, в данных текущего пользователя.
  2. Откройте ccwatch во втором терминале. Список показывает запущенные сессии; новые находятся сверху.
  3. Выберите сессию стрелками ↑ / ↓. Нажмите Enter, чтобы открыть карточку. В ней видны статус, модель, план и последнее действие.
  4. Подключите хук по инструкции ниже. Он нужен для запросов плана, отправки советов и сообщений агенту.

Для первого запуска достаточно одной активной сессии. Если список пуст, перейдите к диагностике: ccwatch зависит от локального реестра сессий Claude Code.

ШАГ 03

Подключите связь с агентом

Хук — команда, которую Claude Code вызывает после использования инструмента. Через неё ccwatch передаёт запросы выбранной сессии. Для просмотра локальных данных подключать его не обязательно.

  1. Сначала выберите постоянное расположение программы. При настройке сохраняется абсолютный путь к бинарнику.
  2. В карточке сессии нажмите s и выберите совет «Хук ccwatch не подключён». Если подключён старый Node-хук, появится предложение переключить его на программу.
  3. Нажмите Enter. Прочитайте предлагаемое изменение ~/.claude/settings.json и подтвердите клавишей y. Любая другая клавиша отменяет изменение.
  4. В Claude Code проверьте регистрацию через /hooks. При необходимости перезапустите сессию, чтобы применить настройки.
  5. Вернитесь в карточку ccwatch и нажмите p. Продолжите задачу в Claude Code и дождитесь вызова инструмента и ответа агента.
Запрос не доставляется мгновенно.

Он ждёт следующего события PostToolUse. Если агент простаивает, запрос продолжает ждать. Отметка доставки означает передачу контекста агенту; план или ответ появится после того, как агент его обработает.

В живом режиме с подключённым хуком монитор сам просит план, если сессия занята более 30 секунд и плана ещё нет. Отключить автоматический запрос: ccwatch --no-ask. Ручная клавиша p остаётся доступна.

Подключение хука меняет настройки Claude Code для пользователя. Не удаляйте другие хуки при ручном редактировании. Формат и поведение хуков проверяйте в документации Claude Code.

ШАГ 04

Работайте с карточкой сессии

Следите за планом

Enter открывает полный план. ✓ отмечает готовое, ▶ — текущий шаг. Используйте стрелки, PgUp / PgDn, Home / End. Оценки времени берутся из плана агента: прогноз не гарантирует точное время завершения. Если план не появился, запросите его через p.

Читайте таблицу токенов

«Выход» — токены ответов, «вход» — входные токены, «из кэша» — чтение кэшированного контекста. Работа главного агента и субагентов показана отдельно. «Контекст» помогает следить за размером контекста сессии. «Доля» рассчитывается по встроенным коэффициентам цены: это не счёт за API и не остаток лимита подписки.

Применяйте советы

Нажмите s, выберите совет и прочитайте описание. Enter отправляет совет агенту либо показывает изменение настройки для советов «для вас». a отправляет все доступные советы для агента. u открывает скрипт настройки, если он предусмотрен. Изменение выполняется только после показа правки и подтверждения y.

Для обратимых правок повторный запуск того же скрипта использует журнал изменений, чтобы вернуть прежнее значение. В списке советов можно видеть отправку, реакцию агента и оценку эффекта. Доставка совета не означает, что агент уже выполнил его.

Скиллы, идеи и сообщения

i открывает обнаруженную историю скиллов: названия, количество вызовов и кто их вызывал. b открывает идеи по улучшению анализатора; Enter на этом экране отправляет вопрос агенту. m в карточке позволяет набрать собственное сообщение. Enter отправляет его, Esc отменяет, Ctrl+U очищает ввод. Сообщение тоже доставляется через хук.

Выйдите или завершите сессию

q и Ctrl+C закрывают монитор, оставляя Claude Code работать. x в карточке завершает CLI-сессию с дочерними процессами после подтверждения y; текущая работа прерывается. Транскрипт сохраняется, продолжить можно через claude --resume <ID>. Десктопную сессию закрывайте в самом приложении Claude.

Команды запуска

Примеры предполагают установленную команду ccwatch. В PowerShell её можно заменить на .\target\release\ccwatch.exe.

КомандаРезультат
ccwatchЖивой режим с обновлением примерно раз в секунду
ccwatch --onceОдин снимок в консоль и выход
ccwatch --session XСессия по части имени или префиксу ID
ccwatch --session X --planСразу полный план
ccwatch --session X --tipsСразу советы
ccwatch --session X --skillsСразу история скиллов
ccwatch --bellЗвуковой сигнал, когда сессия перестала быть занятой

ccwatch --helpВстроенная справка

Если имя содержит пробелы, используйте кавычки: ccwatch --session "my project". Для завершённой сессии укажите полный ID; просмотр зависит от наличия транскрипта на диске.

Снимок в файл
ccwatch --once > snapshot.txt

Без терминала на вводе или выводе программа сама переходит в режим снимка. Снимок может содержать названия задач и локальные пути — проверьте его перед публикацией.

Где хранятся данные

~ — домашняя папка пользователя, обычно C:\Users\имя на Windows. Монитор читает реестр сессий и транскрипты Claude Code, а запросы и журнал своих настроек хранит отдельно.

ПутьНазначение
~/.claude/sessions/Реестр запущенных сессий
~/.claude/projects/Транскрипты сессий и субагентов
~/.claude/settings.jsonНастройки Claude Code, включая PostToolUse
~/.ccwatch/ask/Запросы, ожидающие хука
~/.ccwatch/done/Отметки доставки
~/.ccwatch/plans/Планы прежнего файлового формата
~/.ccwatch/settings-log.jsonЖурнал изменений для возврата настроек
~/.ccwatch/ideas.jsonl, ideas/Собранные идеи и ответы агентов

Нестандартное расположение

CLAUDE_CONFIG_DIR меняет корень данных Claude Code, CCWATCH_DIR — рабочую папку монитора. У монитора и процесса хука должны быть одинаковые значения. Непустая переменная NO_COLOR отключает цвет.

Пример PowerShell — замените пути своими
$env:CLAUDE_CONFIG_DIR = 'D:\claude-config'
$env:CCWATCH_DIR = 'D:\ccwatch-data'
ccwatch

Если что-то не работает

Список сессий пуст

Запустите локальную сессию Claude Code. Проверьте, что в ~/.claude/sessions/ есть записи и они относятся к работающим процессам. Сверьте пользователя и CLAUDE_CONFIG_DIR. Сессия другой машины не появится без её локальных данных. Формат реестра зависит от версии Claude Code.

План или сообщение остаётся в ожидании

Проверьте хук через /hooks в Claude Code, путь к бинарнику и окружение. Продолжите задачу: нужен вызов инструмента именно выбранной сессии. Доставка и ответ агента происходят в разное время. Автоматический запрос имеет срок ожидания 10 минут, ручной — до 12 часов.

После перемещения программы хук перестал работать

В настройках остался старый абсолютный путь. Запустите программу из нового постоянного места и подключите хук заново через советы. При ручном редактировании изменяйте только хук ccwatch.

Терминал показывает снимок и сразу закрывает программу

Живой режим включается только при терминале на вводе и выводе. Запустите без перенаправления и без --once. Для читаемого интерфейса увеличьте ширину и высоту окна.

Не находится cargo или сборка требует linker

Установите Rust, проверьте cargo --version и откройте новый терминал. На Windows с MSVC toolchain установите компоненты C++ и Windows SDK через Visual Studio Build Tools. Повторите cargo build --release.

Совет доставлен, но изменений не видно

Доставка подтверждает передачу запроса. Агент ещё должен обработать совет; часть советов выполняется пользователем через подтверждаемую правку настроек. Проверьте описание и статус совета.

Для сообщения о проблеме приложите команду запуска, ОС и обезличенный вывод ccwatch --once. Открыть issue на GitHub ↗

Обновление

В папке исходников получите изменения и пересоберите программу. Сначала сохраните собственные изменения, если они есть.

git pull --ff-only origin master
cargo build --release

При установке в Cargo bin обновите установленную команду:

cargo install --path . --force

Если расположение бинарника поменялось, перенастройте хук. Для проверки доступных команд используйте ccwatch --help.
